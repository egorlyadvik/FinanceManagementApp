# Личные финансы

Консольное приложение на Java для учёта доходов и расходов. У каждого пользователя свой кошелёк с операциями, категориями и лимитами расходов.

## Запуск

Нужны JDK 17 и Maven. Из папки проекта выполните:

```bash
mvn verify
java -jar target/FinanceManagementApp-1.0-SNAPSHOT.jar
```

В IntelliJ IDEA можно запустить `verify` из окна Maven. При первой сборке Maven загрузит JUnit и плагины сборки. Само приложение использует стандартную библиотеку Java.

## Команды

Введите команду и нажмите Enter. Каждый параметр вводится отдельной строкой по подсказке программы.

| Команда | Параметры по порядку | Действие |
| --- | --- | --- |
| `register` | Логин, пароль | Создать аккаунт |
| `login` | Логин, пароль | Войти в аккаунт |
| `logout` | - | Выйти из аккаунта |
| `category` | Название | Создать категорию |
| `rename` | Текущее название, новое название | Переименовать категорию |
| `income` | Категория, сумма | Добавить доход |
| `expense` | Категория, сумма | Добавить расход |
| `budget` | Категория, лимит | Установить лимит расходов |
| `report` | Enter для всех категорий или список через `;` | Показать отчет |
| `report-file` | Выбор категорий как в `report`, путь к файлу | Сохранить отчет |
| `export` | Путь к CSV-файлу | Выгрузить кошелёк в CSV |
| `import` | Путь к CSV-файлу | Загрузить кошелёк из CSV |
| `transfer` | Логин получателя, сумма | Оформить перевод |
| `help` | - | Показать справку |
| `exit` | - | Завершить работу |

Логин состоит из 1–30 символов. В любой позиции допустимы строчные латинские буквы, цифры, дефисы и подчёркивания. Категории можно называть по-русски и использовать пробелы внутри названий. В названии запрещены точка с запятой и двойные кавычки. Суммы операций и лимиты бюджета должны быть больше нуля. Для дробных сумм используйте точку и до двух знаков после неё, например `300.50`.

### Пример ввода

```text
register
mary
demo123
login
mary
demo123
category
Зарплата
category
Еда
category
Такси
income
Зарплата
63000
budget
Еда
4000
expense
Еда
800
expense
Такси
1500
report
Еда;Такси
exit
```

Сводка по выборке покажет общие расходы `2300.00` и остаток бюджета на еду `3200.00`. Чтобы увидеть общий доход `63000.00`, после команды `report` нажмите Enter без ввода категорий. Доходы, расходы и бюджеты выводятся отдельными списками. Доходы и расходы суммируются за всю историю выбранных категорий.

При переводе у отправителя появляется расход, у получателя - доход. Обе операции записываются в служебную категорию «Переводы» с логином второй стороны. Название категории фиксировано, а её лимит можно изменить командой `budget`. Для перевода нужно иметь достаточный баланс. При обычном расходе баланс может уйти в минус, и программа предупредит об этом. Оповещения о бюджете появляются при расходовании от 80% лимита и при его превышении.

## Хранение данных

Кошельки хранятся в памяти во время работы. Команды `logout` и `exit` сохраняют кошелёк текущего пользователя и кошельки получателей переводов в `data/wallets.properties` относительно папки запуска. При входе нужный кошелёк загружается обратно. При регистрации пароль сохраняется открытым текстом в `data/accounts.properties`. Для локальной проверки используй тестовые пароли.

CSV-снимок в UTF-8 содержит категории, бюджеты и операции. Успешный импорт целиком заменяет текущий кошелёк. Повторный экспорт по тому же пути перезаписывает файл.

Первая строка CSV — `type;category;amount;anotherUserLogin`. Каждая следующая строка должна содержать ровно четыре поля, разделённых `;`:

| Тип строки | `category` | `amount` | `anotherUserLogin` |
| --- | --- | --- | --- |
| `CATEGORY` | Новая категория | Пусто | Пусто |
| `BUDGET` | Ранее объявленная категория | Положительный лимит, до двух знаков после точки | Пусто |
| `INCOME`, `EXPENSE` | Ранее объявленная категория | Положительная сумма, до двух знаков после точки | Логин второй стороны или пусто |

Пустые поля сохраняют разделители: например, `CATEGORY;Еда;;` и `EXPENSE;Еда;300.50;`. Логин второй стороны проверяется по тем же правилам формата, что и при регистрации. Пустые строки внутри снимка, лишние или недостающие столбцы, неизвестные типы строк и некорректные значения приводят к отказу от импорта с номером строки и причиной ошибки. Текущий кошелёк при этом сохраняет прежнее состояние, и приложение продолжает читать команды.

## Архитектура

| Пакет | Ответственность |
| --- | --- |
| `core.model` | `Wallet` хранит категории и операции, считает баланс и бюджеты. `Operation` описывает операцию, а `OperationType` задаёт её тип. |
| `core` | `FinanceService` отвечает за регистрацию, вход, сохранение и переводы. `FinanceStorage` задаёт интерфейс хранения аккаунтов и кошельков. `NotificationRules` определяет условия оповещений о бюджете и балансе. |
| `infra` | `FileFinanceStorage` сохраняет аккаунты и кошельки. `CsvWalletFile` читает и записывает снимки кошельков. |
| `cli` | `ConsoleApp` читает команды и параметры и использует `CsvWalletFile` для импорта и экспорта. `ConsoleReport` выводит сводку и оповещения. |
| Пакет по умолчанию | `Main` создаёт компоненты приложения и запускает CLI. |

## Проверки

- `mvn test` запускает модульные и интеграционные тесты.
- `mvn verify` запускает тесты, собирает JAR и проверяет стиль через Checkstyle.

Тесты проверяют расчёты, бюджеты, переименование категорий, вход, сохранение, переводы, CSV и сценарии CLI. Файловые тесты используют временные папки.
